# 岗位匹配与投递说明

对照来源：用户提供的「全栈工程师（AI 伴侣 / AI 应用与 Agent 方向）」JD 截图。本说明评估 rain-cafe 这个项目能够提供的证据，不代替个人简历、其他项目或面试能力评估。

在线演示：[雨隙 · 雨夜咖啡馆](https://xiujiegmail.github.io/rain-cafe/)

GitHub：[xiujieGmail/rain-cafe](https://github.com/xiujieGmail/rain-cafe)

## 真实模型与语音服务为何尚未启用

当前项目处于交互与工程流程验证阶段。已实现本地 Next.js 后端的 LLM、STT、TTS 调用接口，但尚未配置真实供应商凭据，也未完成外部服务实测。此阶段优先完成角色状态、结构化演出、录音生命周期、轮次取消和失败恢复，真实服务配置与效果验收属于后续工作。

演示采用确定性的剧情规则和预录语音，有助于复现打断、延迟、超时和媒体失败，方便评审无需密钥即可查看互动体验。这种演示能提供交互工程证据，但不能证明模型自由对话质量、识别准确率、真实调用延迟或实际服务成本。

在线版另外受 GitHub Pages 静态托管限制，不运行动态 API；实际录音识别和真实模型对话需要运行本地完整后端，或后续部署支持 Node.js 的后端。不能把 Pages 的限制作为本地真实服务尚未验收的全部原因。

## 可用于投递的项目描述

> 雨隙 · 雨夜咖啡馆是基于 Next.js、React 和 TypeScript 的 AI 角色互动 MVP。围绕文字输入、语音播放、角色演出和用户打断构建交互闭环，实现轮次取消、迟到结果拦截、结构化演出校验与故障降级，并提供移动端适配、自动化测试、公开演示和源码。当前公开版为无需密钥的 Mock 演示；本地后端已实现 LLM / STT / TTS 接入代码，真实供应商配置及端到端效果验收尚待完成。开发过程中使用 AI 辅助，参与范围与验证记录见 AI_USAGE.md。

JD 还要求说明个人负责部分。投递前请根据实际经历补充需求判断、架构决策、代码实现、测试或部署中本人承担的内容；本仓库不预先代填未经确认的个人贡献，不将 AI 生成代码全部表述为独立手写。

## 投递前最值得补充的证据

1. 优先配置真实 STT / LLM / TTS，录制 3–5 分钟真实交流，展示自由追问、角色一致性、演出与说话中打断。记录供应商、模型、延迟和失败恢复结果。
2. 用短文说明本人能解释的关键决策：轮次为什么先失效再清理、旧回复如何拦截、字幕何时发布、音频失败如何降级，以及接口密钥如何留在服务端。
3. 如果没有其他项目证明 ComfyUI 与 Agent 能力，再补一个实际运行并可复现的最小案例，例如服务端调用 ComfyUI 工作流并展示生成状态与失败结果；完成后再计入岗位证据。
4. 数据库、账号、支付、队列与监控可由其他真实项目提供证据；无需为了投递把所有平台功能堆入当前角色互动 MVP。

可以先附此作品投递，但「仅跑通流程」的定位说明无法替代 JD 要求的真实 AI 接入证据。完善文档能让范围更清楚，补一次真实服务演示则会更直接地提高岗位相关性。
