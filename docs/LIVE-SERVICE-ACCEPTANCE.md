## 真实 HTTP 验证

测试音频为合成中文语音，不是物理麦克风采集的人声。接口实际上传音频并请求硅基流动，无固定转写或 Mock 回复替代。

| 步骤 | 输入 / 结果 | 单次耗时 |
| --- | --- | --- |
| WAV 识别 | 项目中文问候 WAV → 实际中文转写，HTTP 200；人名与个别词有识别误差 | 约 5.2 秒 |
| WebM 识别 | 合成「我可以看看你拍的照片吗？」→ 同句转写，HTTP 200 | 免费模型阶段约 4.7 秒；Pro 完整链路测试约 19.1 秒 |
| Pro 角色回复 | 「当然可以，这是海边车站的照片。」；合法 `show_camera`、`travel_photo` 事件，HTTP 200 | 约 1.7 秒 |
| 回复语音合成 | 上述台词 → MP3，50,815 字节，HTTP 200 | 约 0.7 秒 |
| 历史追问 | 携带首轮问答，问照片在哪里拍摄 → 保持照片话题，HTTP 200 | 约 2.0 秒 |

模型自行补充了北海道地点，这是角色生成内容，不是检索验证的地理事实。上述数据仅为少量调用记录，不是延迟分位数或可用性承诺。STT 有明显波动，连续自然交谈效果仍需实测。

## 浏览器完整录音链路

Chromium 自动化将合成中文音频通过 AudioContext 的 MediaStream 注入 `getUserMedia`，应用使用真实 MediaRecorder 录制并上传，再请求真实 STT、LLM 和 TTS。

已观察到识别文本「我可以看看你拍的照片吗？」、角色回复、照片展示及 Audio `playing` / `ended` 事件；录音轨道最终为 `ended`。这验证了浏览器录制、上传和真实音频播放链路，不证明实际设备授权、环境噪声识别效果或人工听到的声音质量。

另外，在真实合成音频触发 `playing` 后自动点击录音入口，观察到旧 Audio 的 `paused` 为 true、页面进入 `listening`、旧照片清除；已结束录音的轨道为 `ended`。自动化浏览器随后关闭，最终在用的测试流随页面关闭释放。实际耳朵听到的中断速度仍待人工确认。

## 免费模型与协议修正

免费 `XingChenAGI/Xing4.0-29B` 首次完整角色请求出现 25 秒超时。免费 `Qwen/Qwen2.5-7B-Instruct` 曾约 1.3–1.5 秒成功返回，但历史追问也出现 25 秒超时。共享资源负载或网络情况可能有关，本次未定位供应商内部原因。

因此本地改用低价 Pro 模型。系统提示词补充英文枚举与照片事件 JSON 示例，避免小模型把资源 ID 翻译为中文；最大输出限制为 512 tokens，服务端继续校验白名单。短期成功不保证长期稳定，失败仍由现有超时、重试入口与字幕降级处理。
