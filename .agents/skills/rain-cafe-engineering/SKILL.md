# 雨隙工程规范

修改前阅读仓库 AGENTS.md 和相关模块；修改 Next.js API 时查阅当前安装版本的文档。规范适用于本仓库所有后续开发。

## 注释

- JS/TS/TSX/MJS 的人工说明使用中文 `// xxx`。解释原因、边界条件或生命周期，不逐行翻译代码。
- 轮次取消、迟到结果拦截、资源释放、录音转换、服务端校验、超时与媒体降级等关键位置必须保留说明，行为改变时同步更新。
- CSS 使用合法的中文 `/* xxx */`，Shell/环境配置/YAML 使用中文 `# xxx`；不要在这些文件中强行使用 `//`。机器指令、许可证和生成文件按工具要求保留。

## 代码与交互

- 保持 TypeScript strict；禁止显式 any，外部数据从 unknown 开始校验。接口输入和模型场景协议使用 Zod，禁止任意媒体 URL 或未经验证的演出指令。
- 维持 UI、交互引擎、浏览器服务、服务端 Provider 的职责边界；优先修复现有模块，只有职责明确时才新增抽象。
- 每次新输入先让旧轮失效并取消；异步结果、播放回调与演出提交均检查有效轮次。取消不得提交旧音频或恢复旧字幕。
- 成功、失败、取消和卸载均释放轨道、音频、ObjectURL、定时器和监听器；清理须幂等。辅助音量检测失败允许继续录音，但必须注释理由。
- 保留移动端布局、可访问标签和明确错误恢复入口；禁止把模拟识别或预录声音描述为真实模型调用。
- 密钥只在服务端读取。禁止 NEXT_PUBLIC 密钥、前端硬编码密钥或将 .env.local 放入源码、截图、日志、静态产物及提交。

## 验证与交付

- 执行 `npm run check`（类型、ESLint、测试）和 `npm run build`；交互/API 变更运行相关 smoke。为取消竞争、资源释放、输入校验等实质风险补充回归测试，不为普通注释改动重复编写测试。
- 更新 README、AI_USAGE 与 docs/ACCEPTANCE.md：区分自动检查、用户报告的人工验收与待验证项，不虚构工时、性能或手机实机结果。
- 提交前执行 `git diff --check`，检查暂存清单和密钥泄漏；不提交依赖、构建缓存或私有环境。只有用户授权时发布，源码推送不会自动更新 Pages。
- 公共 Pages 只能发布无密钥的静态 Mock；真实 STT → LLM → TTS 使用本地或独立后端。
